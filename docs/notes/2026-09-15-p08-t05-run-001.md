# P08-T05 — production candidate run 001

Status: implementation and real CLI run complete; P08-T05 evidence is recorded. P08-T06 remains open.

## Bug and root cause

The initial `AMANDA-RUN-001/run.json` had 24 macro candidates, no attempt ledger, no ranking/Pareto safety sets, and 24 `sector_missing` rejections with an empty sector id. The source requirements are nested under `sectors`, while each space has no `sector` field. The existing `constraints.py` working-tree fix correctly uses the parent sector `logical_id`.

The production call also used 24 seeds without passing the six configured archetypes. `generate_designs()` therefore generated one `DEFAULT` stream. A second independent defect surfaced after six-stream coverage: cumulative floating-point room-strip heights could exceed a block boundary by about `1e-14 m`, producing `room_outside_block` for otherwise area-matching blocks.

## Minimal correction

- `run_pipeline()` now accepts configured archetypes and records one real attempt per archetype/seed pair, with outcome partition `valid`, `invalid`, `unknown`, or `duplicate`.
- The production CLI activates the six YAML archetypes with seeds `0..23`, stores engine/input versions, hard rejection counts, ranking, and Pareto ids, and publishes only hard-valid unique candidates to ranking/Pareto.
- `rooms.py` snaps the final strip endpoint to the block boundary only when the difference is within `1e-9 m`; genuine geometry overflow remains rejected.
- The pre-existing `constraints.py`, `generate.py`, and new production tests were preserved and included in the scoped change.
